# **1. Masalah arsitektur terbesar: belum ada UI governance**

Saat ini setiap halaman punya kebebasan mendefinisikan styling, motion, dan interaksi sendiri.

Contohnya:

- `home.tsx` mempunyai animasi sendiri.
- `journal.tsx` mempunyai mekanisme animasi daftar sendiri.
- `keuangan.tsx` mempunyai easing dan variasi transisi sendiri.
- `stats.tsx` mempunyai animasi grafik sendiri.
- `motion-kit.tsx` menyediakan animasi reusable.

Ini masih bisa dikelola ketika halaman sedikit. Namun semakin banyak fitur, akan semakin sulit menjaga konsistensi.

Saya merekomendasikan membuat tiga sistem terpusat:

## **Rutina UI Governance**

**01. Design System**

Bagaimana tampilan aplikasi harus dibentuk.

CSS tokens, typography, color roles, spacing, elevation, responsive rules.

**02. Interaction System**

Bagaimana pengguna berinteraksi.

Gesture, navigation, dialog, sheet, keyboard, focus, feedback.

**03. Motion System**

Bagaimana seluruh elemen bergerak.

Timing, easing, choreography, spring, transitions, reduced motion.

**Rutina Product Screens**

Home · Journal · Finance · Statistics · Profile

Aturan pentingnya: developer tidak boleh menentukan sendiri semua warna, radius, dan motion setiap kali membuat komponen baru.

## **C. Migrasikan Counter ke MotionValue**

Ini temuan yang sangat konkret.

File: [counter.tsx](https://github.com/anandategarch/rutina-2.0/blob/main/src/components/rutina-mobile/counter.tsx?utm_source=chatgpt.com)

Saat ini kamu menggunakan:

```
useMotionValueEvent(spring, "change", (v) => {
  setText(formatValue(v));
});
```

Artinya React state diperbarui berulang kali selama animasi angka.

Untuk kasus seperti ini, gunakan MotionValue langsung.

```
"use client";

import {
  motion,
  useInView,
  useSpring,
  useTransform,
} from "motion/react";

import { useEffect, useMemo, useRef } from "react";

export function Counter({ to }: { to: number }) {
  const ref = useRef<HTMLSpanElement>(null);
  const inView = useInView(ref, { once: true });

  const spring = useSpring(0, {
    stiffness: 55,
    damping: 16,
  });

  const formatter = useMemo(
    () => new Intl.NumberFormat("id-ID"),
    []
  );

  const formatted = useTransform(
    spring,
    (value) => formatter.format(value)
  );

  useEffect(() => {
    if (inView) {
      spring.set(to);
    }
  }, [inView, to, spring]);

  return (
    <motion.span ref={ref}>
      {formatted}
    </motion.span>
  );
}
```

Keuntungannya: MotionValue dapat memperbarui nilai tampil tanpa harus membuat React render pada setiap frame animasi.&#x20;

# **4. Anime.js: Advanced Choreography Architecture**

Saya akan memperlakukan anime.js sebagai engine khusus untuk animasi kompleks.

Bukan sebagai pengganti Motion.

## **A. Ada konflik kepemilikan animasi di source sekarang**

Ini temuan yang layak menjadi prioritas refactoring.

Pada `journal.tsx`:

- Motion mengatur scale artikel lewat `whileTap`.
- Anime.js mengatur `translateY` dan `opacity` pada artikel yang sama.

Pada `profile.tsx`:

- Beberapa elemen sudah mempunyai animasi Motion.
- Anime.js kembali mengatur `translateX` dan `opacity` melalui `[data-row]`.

Potensi konflik muncul ketika dua engine mengontrol properti CSS yang sama pada node yang sama.

Solusi paling aman:

**Animation Ownership Rule**

**Satu properti, satu animation owner.**

- Motion mengatur transform kartu.
- Motion atau Anime mengatur opacity, bukan keduanya.
- CSS mengatur hover sederhana yang tidak perlu timeline.
- Anime.js mengatur SVG dan choreography yang terisolasi.

Bila harus menggunakan dua engine, gunakan nested wrapper:

```
<motion.article whileTap={{ scale: 0.97 }}>
  <div className="animation-inner">
    {/* Anime.js hanya mengatur elemen dalam */}
  </div>
</motion.article>
```

Namun lebih baik tetap memilih satu engine jika animasinya sederhana.

## **B. Gunakan createScope Anime.js**

Kamu menggunakan anime.js 4.5.0.

Saya menyarankan memakai `createScope()` sebagai standar untuk komponen animasi.

```
import { useEffect, useRef } from "react";
import { animate, createScope, stagger } from "animejs";

export function AnimatedIllustration() {
  const root = useRef<HTMLDivElement>(null);

  useEffect(() => {
    if (!root.current) return;

    const scope = createScope({
      root,
      mediaQueries: {
        reduceMotion: "(prefers-reduced-motion: reduce)",
      },
    }).add((self) => {
      const reduceMotion = self.matches.reduceMotion;

      animate(".illustration-path", {
        strokeDashoffset: [100, 0],
        delay: reduceMotion ? 0 : stagger(80),
        duration: reduceMotion ? 0 : 900,
        ease: "outExpo",
      });
    });

    return () => {
      scope.revert();
    };
  }, []);

  return (
    <div ref={root}>
      <svg>
        <path className="illustration-path" d="..." />
      </svg>
    </div>
  );
}
```

Manfaatnya:

- Semua selector berada dalam scope komponen.
- Instance animasi dapat dibersihkan bersama.
- Bisa mengatur media query.
- Bisa mengatur reduced motion secara langsung.

Anime.js mendokumentasikan Scope untuk kebutuhan komponen, responsive animation, dan batch reversion.&#x20;

```
  defaultValues,
});
```

Setiap form harus mempunyai:

- Inline validation.
- Error message yang jelas.
- Loading state.
- Disabled submit state.
- Success feedback.
- Proteksi double submit.

Ini membuat interaksi lebih profesional daripada sekadar menampilkan toast ketika input kosong.

# **6. Advanced Rendering & Performance Architecture**

Sekarang masuk ke bagian yang sering terlewat ketika membangun aplikasi dengan banyak animasi.

**Tampilan yang mulus tidak selalu berarti aplikasi ringan.**

Saya ingin kamu mengaudit tiga level performa.

### **A. React rendering**

Di Rutina, Zustand menjadi sumber state untuk banyak halaman.

Pertahankan selector granular seperti:

```
const habits = useRutina((s) => s.habits);
const completions = useRutina((s) => s.completions);
```

Hindari mengambil seluruh store:

```
const state = useRutina();
```

Untuk object hasil selector yang dibuat setiap render, gunakan `useShallow` atau selector yang stabil.

Pisahkan juga:

- Habit state.
- Journal state.
- Finance state.
- Temporary UI state.

Jangan menyimpan status modal, transaksi, dan histori kebiasaan dalam satu objek domain yang tidak terorganisasi.

### **B. Animation rendering**

Saya ingin semua animasi diklasifikasikan:

| Properti            | Penggunaan                                    |
| ------------------- | --------------------------------------------- |
| Transform           | Posisi, scale, rotation                       |
| Opacity             | Fade                                          |
| Width/height        | Hanya jika perubahan layout memang diperlukan |
| Filter              | Terbatas                                      |
| Background position | Efek khusus                                   |
| Box shadow          | Hindari animasi besar berulang                |

Pada progress bar, utamakan transform daripada perubahan width yang memicu layout. Gunakan Chrome Performance dan Paint Flashing untuk membuktikan bahwa perubahan memang meningkatkan performa.&#x20;

### **C. Bundle architecture**

Satu hal yang saya lihat: `package.json` masih mencantumkan dua dependency:

```

  "framer-motion": "^12.23.2",
  "motion": "^14.14.0"

```

Kode yang saya periksa menggunakan `motion/react`. Saya belum menemukan import langsung `framer-motion` di hasil pencarian source.

Saya menyarankan pemeriksaan:

```

```

Jika tidak ada penggunaan, hapus dependency lama setelah memastikan tidak dipakai di bagian repository lain.

Selanjutnya jalankan:

```
bun run next experimental-analyze --output
```

Ini dapat membantu mengidentifikasi dependency berat, termasuk Recharts dan modul yang masuk ke client bundle. Next.js 16.1+ menyediakan analyzer untuk inspeksi ukuran dan rantai import.&#x20;

# **7. Accessibility dan motion preferences tingkat lanjut**

Saya ingin Rutina bukan hanya cantik di mouse dan touch screen, tetapi juga bagus ketika digunakan dengan keyboard atau perangkat bantu.

Ada satu hal penting: `MotionConfig reducedMotion="user"` tidak otomatis mengatur seluruh animasi anime.js dan CSS custom.

Gunakan:

- `useReducedMotion()` untuk mengubah perilaku Motion.
- `createScope` dengan media queries untuk anime.js.
- `prefers-reduced-motion` untuk CSS.
- Hindari animasi parallax dan floating kontinu ketika pengguna meminta gerakan minimal.

Motion menyediakan hook khusus yang merespons pengaturan reduced motion perangkat.&#x20;
